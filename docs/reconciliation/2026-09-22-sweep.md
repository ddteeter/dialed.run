## The rule

The artboards are the truth for composition — what a screen contains, where
it sits, the hierarchy, the copy, which states exist (CLAUDE.md, "Design
truth"). Contracts outrank them only on **values**. So every difference
below is classified mechanically, not by taste:

| class              | meaning                                                                                          | who acts  |
| ------------------ | ------------------------------------------------------------------------------------------------ | --------- |
| **drift**          | built, differs from the board, no record says it should. **The default.**                        | us        |
| **bug**            | a defect in shipped behaviour the comparison exposed, independent of composition                 | us, first |
| **recorded**       | differs, and a decision exists (`docs/decisions.md`, a design-deltas ruling) — confirm it stands | the owner |
| **board conflict** | two boards disagree; a contract board outranks a screen board                                    | design    |
| **unbuilt**        | the board marks it `data-status="unbuilt"` — skipped                                             | —         |
| **data**           | the board's invented values (names, times, counts) — not a finding                               | —         |

"Deliberate" is not a class. A divergence without a record is drift.

## How

A throwaway Playwright spec seeded a world shaped like the boards — a viewer
with a seven-piece closet in °F and miles, a followed runner (`dana_k`) with
a public dialed entry and a useful reaction, runs at 41°F in light rain, an
unjudged backlog, a finished import — then rendered each board (with the
app's own fonts, annotations and unbuilt regions stripped) and each route,
and dumped reading-order text with its region and T1 colour role. The spec
is deleted; the report and the fixes are what last. Conformance specs lock
each screen in as it is fixed.

`status-bar` on the boards is the phone's own clock and battery, not app
UI, and is excluded.

## Bugs — fix first

These are defects, not composition; three of them are mine from task 115.
**All four are fixed** on `feat/reconcile-sweep`, each with a test that
fails against the old code.

1. **`formatDuration` never produces hours.** `src/lib/measures.ts` renders
   minutes and seconds only, so a 1h 03m 41s run reads `63:41`. The boards
   draw `1:03:41`. Every run over an hour, on every surface that shows a
   duration (D, DS2, run lists). **Fixed** — `h:mm:ss` from one hour.
2. **DS2's conditions line ignores the runner's units, and shows the wrong
   temperature.** `conditionsLine` in `VerdictBacklog.tsx` writes
   `` `WIND ${Math.round(windKph)}` `` — always kph, labelled "WIND", no
   direction — for a runner set to miles. It also leads with _feels-like_
   where the board shows the actual temperature, and drops humidity. Board:
   `41°F · 88% · MIST · SE 9`. Build: `36° · light rain · WIND 15`.
   **Fixed** — actual temperature, and `formatWind` in the runner's units:
   `41° · light rain · 9mph`. Still short of the board by two fields:
   humidity is stored but not in `Conditions`, and wind direction is not
   stored at all — both drift, the second **needs data**.
3. **DS2's rail renders design's commentary as UI copy.** "Verdicts saved
   here count exactly like verdicts from the phone. There's no bulk rule —
   every row is one run." is `data-annotation` on the Desktop Contract — a
   note to us — and task 115 shipped it as the rail's body. **Fixed**, and
   guarded: `test/architecture/annotations-are-not-copy.test.ts` scans every
   annotation sentence on every board against every component's rendered
   text. A scan at the time found no second leak.
4. **C's coverage marker is teal.** `[Untested]` renders `--dialed-text`.
   T2: teal means _dialed_; round 16: "coverage is monochrome per AB, so
   nothing in the rail carries a hue." **Fixed** — `--muted`, for the tested
   range as well, which had the same teal.
