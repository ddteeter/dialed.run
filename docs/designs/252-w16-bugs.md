# Design: 252 wave-16 bugs lane

## Problem

This lane has one code fix, one test fix and three sets of diagram fixes,
all on the friends path (owner, 2026-11-18):

- **#881:** a garment's link line says a failed product read is
  "retrying" for the product's whole first day. The sweep, though, stops
  after 6 tries.
- **#897:** a RunnerSearch dom test reads the status region too early.
- **#862, #863, #864:** the enrichment diagram audit found 16 places where
  the `enrichment.c4` stories disagree with the code.

## Approach

- **#881: the line and the sweep share one rule.** `enrichment/abandon.ts`
  gains the "the sweep still owes this a retry" rule, written twice from the
  same two constants (`ENRICHMENT_RETRY_WINDOW_S`, `ENRICHMENT_SWEEP_TRIES`):
  - `isSweepOwed(createdAt, tries, now)` for code;
  - `sweepOwed(now)`, the same rule as SQL.

  `dispatch/scheduled.ts`' `failedAndOwed` uses `sweepOwed()`, and the
  closet's `linkedOutcome` uses `isSweepOwed`, which needs the extraction's
  try count, so its read gains `extraction_tries`. Both are exported through
  enrichment's `index.ts`. A worker test runs both versions over the same
  table of rows (inside or past the day, by tries) and requires them to
  agree.
- **#897: the test waits.** `Follow` reports its status from an effect, so
  the band and the region's sentence land in two renders. That is the
  screen's intended order: the count is heard, then the failure. So only
  the test changes: it waits for the region's text with `findByRole`/`waitFor`.
- **#862–#864: the stories.** Each difference is fixed in
  `docs/diagrams/flows/enrichment.c4` (skill `architecture-diagrams`). The
  sources cite today's paths: `dispatch/scheduled.ts`, `ops/desk/gave-up.ts`.
  D12's note matches #881's rule. D5's misleading comment at
  `enqueue.ts:26-27` is corrected.
- **#864 D13, checked against the code: the story was wrong, not the code.**
  A product stays `pending` only while the consumer cannot finish its job:
  the shared page-fetch budget is spent (by design, deferred with no try
  counted), or the dead-letter handler throws (D14). Each firing re-sends it
  and adds a line to that hour's anomaly report, so nothing is silently
  lost. Once the consumer runs, a failure past the product's first day goes
  straight to Gave up (D11). Gave up lists what the system has stopped
  retrying, and a pending product is still being retried. So no bug is
  filed: the story's note gains the cap of 100 a firing and "no age or try
  ceiling; reported hourly until it runs". If the owner wants a ceiling,
  that is a product call to ask.
