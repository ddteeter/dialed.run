# Design: 245 sec-l23

## Problem

SA-L23, the first of two PRs. The upload held every run file to one size
cap, whatever its format, and the FIT decoder did work on every message
of a file that the parser never reads. This PR gives each format its own
cap, tells the runner at upload which one a file is over, and bounds two
costs of a parse that no budget counted. The second PR is design 246.

## Approach

All in `src/modules/runs/`.

- **A cap for each format** (`upload-limits.ts`): `IMPORT_BYTE_CAPS`, with
  FIT at 10 MB and GPX and TCX at 25 MB. `MAX_IMPORT_BYTES` becomes the
  largest of them, which is what a request is held to before its file's
  format is read (the validator, the body cap, a Garmin download).
  `checkUpload` holds the file to its own format's, in the form and again
  on the server, as it does today.
- **The sentence names the format**: "That FIT file is larger than 10 MB."
  and, for GPX and TCX, "That GPX file is larger than 25 MB. Export the
  run as a FIT file instead." Literals, as `tooMany` is, because a
  template there costs the entry chunk; a test pins each number to the
  table.
- **A leaner FIT decode** (`parsers/fit.ts`): `FIT_READ_OPTIONS` turns off
  the decoder's per-message conversions (sub-fields, components, type
  names, `Date`s, merged heart rates). The parser reads the session's own
  numbers and `toDate` already takes a raw timestamp.
- **A developer-field lookup budget** (`parsers/fit.ts`): the decoder's
  listeners count each message at its developer fields times the
  descriptions registered so far, and refuse a file past
  `MAX_DEVELOPER_FIELD_LOOKUPS`.
- **Attributes count toward the XML budget** (`parsers/shared.ts`):
  `MAX_XML_NODES` counts `=` with `<`, before the bytes are decoded.
- **`importUpload`** (the story): its file-check note names the two caps.

## Contract touches

- Schema, bindings, queues, crons, routes: **none**. No `wrangler.jsonc`
  change.
- Screens: A1's refusal for a file over its cap, in the owner's words.

## Owner answers (2026-11-18)

- The sentences above: name the format, and suggest FIT for a text file.
- FIT at 10 MB now. GPX and TCX stay at 25 MB until design 246 lands.

## Test plan

All vitest; each new case fails on `main` first.

- worker `test/runs/upload-limits.test.ts`: each format at its cap and one
  byte over; the table; the sentences; each sentence's number against the
  table. `imports.test.ts`: the server refuses a FIT over the FIT cap and
  stores nothing.
- ui `test/modules/upload-form.dom.test.tsx`: the form shows each
  sentence.
- worker `test/runs/fit.test.ts`: a file at the lookup budget parses and
  one record over is refused; the listeners' arithmetic at small budgets;
  the decoder options, pinned.
- worker `test/runs/gpx.test.ts`: tags and attributes are counted
  together, at the budget and one over.
