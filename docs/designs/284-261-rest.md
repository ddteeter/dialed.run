# Design: 284 the rest of design 261, in one PR

Issue #1149. Integrates design 261's rows B4, B5, B6, B8, B9, B11 and B12
and C1 to C7, built in parallel streams and merged here one commit each.

## Problem

Design 261 planned the module restructure as lanes, each its own PR. After
B1, B2, B3, B7, B10 and B13 merged, every lane left touched the same pins
file, the same owner map and the same generated structure, so each would
have rebased onto the last and asked for the owner's label again. This PR
lands them together: one rebase, one label, one CI run.

## Approach

Streams committed locally; the integrator picked each commit onto main,
kept each move its own commit, re-pinned once with `npm run modules:pin`
and regenerated the structure rather than hand-merging it. Conflicts were
only those (and adjacent import lines); none needed a ruling.

### Departures from designs 258 and 261

- **`weather/backlog` is a sub-module** (B6). Exporting `checkWeatherBacklog`
  from `weather`'s door would have raised its parent-door pin, which A1
  added after 258 was written. The owner chose the sub-module (option a,
  2026-11-27).
- **`requestHolds` goes to `safety/review/request-holds.ts`** (B8), not
  `takedowns`: there it would make `review` import `takedowns`, a barrel
  cycle.
- **`turnstileAttempt` is on `ops/edge`'s door only** (B11): on the `ops`
  parent door it would breach that pin. Its importers use `../ops/edge`.
- **B9 also moves `stillPendingHold`**, added after 261 was measured, so
  feed writes none of `takedown_requests`.
- **`safety` was 93, not 95, before C5**: `runnerNotLeaving` had already
  left (`b316be5aa`).
- **`importJob` leaves `runs`' door** (re-pin): B7 on main and B6 each moved
  one of its two outside callers into `runs`.
- **`isFollowingQuery` is deleted**: a server function no route called
  (coordinator's ruling). `isFollowing` stays, for `profiles.ts`.
- **B12's first step**: `OutboxHandler`, `OutboxHandlers` and `PayloadOf`
  need only the kinds and drizzle's type, so they move to `lib/sql/outbox.ts`;
  `OWED_AGAIN` and `Refused`, named in their docs, stay in `ops/outbox`.
  That ends `weather/store.ts:21`'s import of `ops`.
- **`safety`'s parent door keeps its own eight names** after C5: the
  seven `inputs.ts` schemas and `NoticeBand`, the only files outside its
  sub-modules. 80 import statements in 36 source and 42 test files now
  take the sub-module door; `deletion.c4` cites `settleOpenReviews` at its
  declaring file. The door is under budget, so its `doorWidth` pin leaves.
- **`ops`' and `account`'s parent doors export nothing** after C7 and C6:
  every name lives on a sub-module and nothing imports the parent. Their
  pins (24, and `account`'s 15 after C2) leave. Each `index.ts` stays,
  since the ratchet and the diagram define a module by it.
- **`denyDomainAction` keeps its knip-doors pin** (owner, 2026-11-27): no
  route calls it yet, but it is the app's only path to add a denylisted
  domain, which the UK OSA risk assessment relies on. Operator tool; the
  Desk form is #1166. The pins file has no reason field, so the reason is
  here and in the PR body.
- **`claimRateLimit`** is no longer exported: B12 left it used only inside
  `rate-limit.ts`.

### Dead letters (B12's audit items)

Three writes decided a product's or an import's failure from a read made
before their batch. Fixed here, each with a test that changes the row in
the gap (`test/before-write-batch.ts`) and fails on the previous code:
enrichment's `markFailed` and dead-letter handler hold every write to a
product still `pending`, and the abandonment sweep writes its Gave-up row
under the same `stillParked` its clear uses. The import dead letter needs
a guarded form of the consumer's `Owe` dependency, so it is #1165.
