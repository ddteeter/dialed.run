# Design: 147 The app's `/open-source` page (plan C9)

## Problem

The marketing site and D-137 send people to `app.dialed.run/open-source` for
the app's licences and credits, and the page does not exist. C9 builds it:
`docs/legal/third-party-notices.md` plus the licence of every package the app
ships. **It is not an undesigned surface**: round 29 #9 ruled it ("Built with
thanks", grouped by licence, type first, searchable) and the Round 29 Rulings
board draws it at phone and desk. This builds to that ruling.

## Approach

- **The list is generated, not written** (round 29 #9; derive, don't mirror).
  `scripts/open-source-list.ts` (tsx, like `check-bundle.ts`) writes
  `src/modules/account/open-source-list.json`: the runtime dependency tree
  from `package-lock.json` (`dependencies` transitively, resolved as Node
  does; no peers, no platform binaries, no `@types/*`), each package's
  version, licence, copyright lines and project link read from its own
  `package.json` and LICENSE/NOTICE files; and the type from
  `public/fonts/OFL.txt`'s header, checked against every family
  `ui/fonts.css` serves. Each licence's text is stored once, as the wording
  most of its group ships; a package whose file says something else keeps
  its own.
- **Committed, and regenerated by `prebuild`.** Committed so tests, dev and
  the mutation sandbox (CI's mutation job runs no npm lifecycle) read it
  without generating; regenerated at build so a release is always true to its
  lockfile, whatever git holds. A test fails when a direct dependency is
  missing from it.
- **Why not exactly what the bundles hold.** The lockfile tree is a superset
  (~270 packages; it includes build-time packages such as Babel that sit in
  `dependencies`). Over-attribution is the safe direction. Bundle-exact needs
  a licence plugin in `vite.config.ts` (forbidden zone) or a second,
  sourcemapped build; recommended later only if the owner wants it.
- **Read on the server.** `account/open-source.ts` imports the JSON and the
  notices file as `?raw` strings, parses them (zod; `parseLegalDoc`) inside
  the server function, so neither rides in the client bundle. The loader
  hands the page the rows.
- **Page**: `account/components/OpenSourcePage.tsx`, on LegalPage's reading
  layout (extracted as `ReadingFrame`/`ReadingSection` so both share one).
  Decisions (grouping, order, search, counts) live in `account/open-source.ts`
  as pure functions. Route `src/routes/open-source.tsx` is glue.
- **Notices**: the vendored material and data credits (profanity list,
  Visual Crossing, MediaPipe model, climate zones) render after the groups
  as one section, its `##` headings under it; the file's preamble, which
  speaks to repo readers, is not shown.
- **Linked** from the signed-out footer and Settings › About after Copyright,
  as the ruling says. Every route gate that lets the legal texts through
  lets this page through too.

## Contract touches

- Schema: **none**. Bindings/queues/crons: **none**.
- New route: `src/routes/open-source.tsx` (public, sessionless).
- Screens: round 29 #9 (`/open-source`); `ui/Layout.tsx` footer;
  `onboarding/components/Settings.tsx` About.

## Test plan

- `test/account/open-source.test.ts` (worker): grouping, order, search,
  counts; the committed list parses and covers every direct dependency.
- `test/account/open-source-page.dom.test.tsx` (ui): the thank-you, groups,
  licence text once, Show all, search and its empty line, notices rendered.
- `test/architecture/open-source-route.test.ts`: `/open-source` is
  registered, and wired to the loader and page.
- Footer and Settings tests extended; `e2e/legal/open-source.demo.spec.ts`.
