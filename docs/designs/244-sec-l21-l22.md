# Design: 244 sec-l21-l22

## Problem

Wave 15 lane 15a, second PR: two items the closure of the 2026-11-14
security audit added, tracked by id only in #756 (SA-L21, SA-L22). This
lane keeps request query strings out of the Worker's stored logs, and
gives an owed email whose address the sender refuses an end.

## Approach

- **SA-L21.** `wrangler.jsonc` sets `observability.redact_query_string`,
  so Workers Logs and traces store a request's URL without its query
  string. One key in a human-managed file, under the owner's one-time
  grant (2026-11-18). `test/bindings-conformance.test.ts` pins it (law
  10). Limit: the key covers the query string only, not a path.
- **SA-L22.** Cloudflare's send throws an `Error` with a `code`. Two of
  its codes are ones a single address can earn: it is suppressed, or
  validation refuses the message to it.
  - `modules/email/deliver.ts`: `deliverOwedEmail` parses a thrown
    error's `code` and answers `refused`, with the code, for those two.
    Any other throw is thrown on. `deliverEmail`, what a runner just
    asked for, is unchanged: it throws and its page says so.
  - `modules/ops/outbox-handlers.ts`: the email handler answers a
    refused send as a new outcome, `Refused`, beside `OWED_AGAIN`.
  - `modules/ops/outbox.ts`: a refused row keeps the ordinary retry
    until a runner's email (kind `email`) has been tried
    `OUTBOX_REFUSED_ATTEMPTS` times (8, a little over five days of
    doubling backoff). At that attempt the drain deletes it and reports
    it once as closed unsent, with the row's ids and the code (laws 6
    and 7), and the run's lines count it. The fast path never closes a
    row: it reports and leaves it for the drain. An operator's email
    (`operator_email`) is never closed.
  - **Why not at the first refusal.** Both codes are also what a fault
    of ours earns for every address (a suppressed sender, a malformed
    message), and during one the operator's own mail fails too. The days
    are for that to be noticed before owed mail is discarded, and the
    report names the code so a run of them reads as ours.
  - Every other failure retries as now, for as long as it fails: a
    recipient the binding or the plan does not allow is the
    deployment's fault here, since the binding names no destinations.
  - Telling the runner in the app is a later item (#890). No sentence a
    runner reads changes here.

## Test plan

All vitest, `worker` project. Each fails on today's code first.

- `test/bindings-conformance.test.ts`: the Worker's logs drop query
  strings.
- `test/email/refused-send.test.ts` (new): an owed send refused with
  either code answers `refused` with it; four other codes, no code and a
  non-string code are thrown on; `deliverEmail` still throws. In the
  outbox: a refused row stays owed and is reported below the count and
  one short of it; at it and past it the row is deleted, reported once
  with its ids and code, and counted on a line in both line modes; an
  operator's email and the fast path close nothing; another failure
  retries past the count.
