# Design: 151 `/open-source` from the bundles, not the lockfile

## Problem

`/open-source` (design 147) is generated by `scripts/open-source-list.ts`,
454 lines that re-implement Node's module resolution over `package-lock.json`,
find licence files by regex and parse copyright lines by regex. It lists 272
packages; the two bundles hold **135** (measured with Vite's own report on
this branch). Its parsing is wrong for real packages — seroval's
`MIT License Copyright (c) 2025 …` and jsesc's `Copyright Mathias Bynens`
keep their copyright inside the "licence text" and get a spurious own-text
row — and none of it is tested: `scripts/` is outside the ratchet. R-161
recorded the root cause: bundle-exact needs `vite.config.ts`, which was a
forbidden zone. The owner has approved that edit (2026-10-24).

## Approach

1. **Vite reports what ships.** Vite 8's built-in `build.license`
   (`{ fileName: ".vite/license.json" }`) writes, per environment, every
   package any emitted chunk holds a module of — name, version, SPDX id and
   its licence file's text. Both environments: `dist/client` (27) and
   `dist/server` (133, including `unenv`, which the Cloudflare plugin injects
   and the lockfile walk never saw). No new dependency.
2. **npm describes each package**, read through npm's own
   `normalize-package-data` (follow-up PR): it cuts an author to a name and
   derives a homepage from a hosted repository, so neither is parsed here. `npm query '*'` (npm's own arborist)
   gives each installed package's location, `homepage`, `repository` and
   `author`, joined on `name@version`. That replaces the hand-written
   resolver; the script reads only a NOTICE file and, for the 8 packages
   that ship no licence file (drizzle-orm, @better-auth/utils, …), nothing:
   their group's text covers them, as today.
3. **The text logic moves into the ratchet.** Copyright holders, the
   licence body and the per-group common wording become pure functions in
   `src/modules/account/licence-text.ts`, mutation tested against fixture
   licence files that include the cases above. The ruling needs them
   ("the copyright line is that name", the text "once, inline") and no
   library extracts copyright holders; what changes is that they are tested.
4. **`postbuild` writes the list; it stays committed.** `npm run build` →
   `scripts/open-source-list.ts` (now ~100 lines of plumbing: read two JSON
   files, run `npm query`, call the module, write) → `check:bundle`. The page
   keeps importing the committed `open-source-list.json`, so dev, tests and
   the mutation sandbox are unchanged. Under `CI`, a regenerated file that
   differs from the committed one fails the build ("dependencies changed:
   run `npm run build` and commit the list"). The list cannot change its own
   bundle membership (it is JSON, not a package), so one build is a fixed
   point. `prebuild` loses `generate:open-source`.
5. **Fonts are unchanged**: still `public/fonts/OFL.txt` checked against
   `ui/fonts.css`.
6. **A second tier, "Built with" (owner, 2026-10-24).** Shipping is what the
   licences oblige; it is not all the app owes. The tools that build it —
   every direct `devDependency` plus any direct `dependency` no bundle
   holds (the router generator) — get a row each: name, version, licence,
   project link, from `npm query`. No licence text and no copyright line:
   their licences attach to copies distributed, and none is. Direct only:
   the dev tree is 589 packages and would bury the shipped list, and the
   direct tools are what we chose. The old lockfile list credited none of
   them (it skipped `devDependencies`). The JSON gains a `tools` array;
   the page renders it after the licence groups, searchable like them.
   Design answered it in round 40 (#82): "Tools we build with", last on
   the page after the notices; design-deltas item 82 records the ruling.

## Contract touches

- Schema / bindings / queues / crons: **none**.
- Forbidden zone: `vite.config.ts` (one `build.license` line), owner-approved.
- `open-source-list.json` gains `tools`; `open-source.ts` and the page gain
  the "Built with" tier and nothing else changes shape. Counts drop 272 → 136 and the AGPL group goes (nothing
  bundled is AGPL).
- R-161 closes in `docs/deferred.md`; design 147 gets a pointer here.

## Test plan

- `test/account/licence-text.test.ts` (worker): holders from `(c)`, `©`, bare
  `Copyright Name`, title-and-copyright on one line, several lines, the
  author fallback; body strips titles and preambles; common wording, ties.
- Existing `test/account/open-source.test.ts`: the committed list parses, a
  bundled direct dependency (react, better-auth) is present, every group has
  text. The "every direct dependency is listed" assertion goes: a direct
  dependency that never reaches a bundle (Babel via the router generator)
  is correctly absent now.
- Manual: `npm run build` twice, second is a no-op; `CI=1` with a stale list
  fails.

## Decisions

- Server bundle included: **yes** (owner, 2026-10-24). The Worker is code
  the app ships.
- Build tools credited in their own tier: **yes** (owner, 2026-10-24).
