BACKGROUND

A vision model turns the photo into structured attributes: category, sleeve length, fabric class, weight, wind/water resistance, color. Those attributes feed a thermal-property table that produces an estimated temp range with no run history at all. Multi-garment photos are segmented before classification. The model's output is always presented as a claim the user can correct — corrections are training data.

This is the only place AI touches the recommendation, and it's doing data entry — not guessing how cold you'll feel.

CLOSET: 0 PIECES TAP WHAT YOU OWN
BACKGROUND

The tap-list is generated from cohort frequency — the pieces most commonly owned by runners in the same climate zone, so a Minneapolis runner is offered mittens and a Phoenix runner isn't. Each tap creates a generic garment record carrying only the category's default thermal properties, flagged low-specificity until the user photographs or edits it. Pasted links hit a product-spec extractor (structured scrape → attribute mapping) so brand-published temp ranges seed the record.

One list, always — the climate band ranks it and sets the fold at fourteen, it never removes a row, because a Minneapolis runner needs tights and a singlet. Nothing arrives ticked: a tick means you tapped it. See AA. Next step is P2.5, where generic rows get named — AC.

BACKGROUND

The GPX archive is parsed in bulk, then every run's start coordinate and timestamp hit a historical weather API to backfill conditions — this is why 148 runs can arrive already carrying temperature, humidity, wind, and precipitation. A memorability heuristic ranks runs by extremity and recency (coldest, hottest, wettest, most recent) because those are the ones a human can actually recall an outfit for. Each tagged run becomes a full training example: conditions + kit + implied "worked."

The highest-leverage screen in onboarding. Four taps buys a temperature range no new user could otherwise cover for months.

BACKGROUND

A blended prior: cohort distribution (what similar runners wore in these conditions), the user's seeded runs, their self-reported offset, and a published dressing heuristic as the floor. Weights shift automatically as personal data accumulates — the source bars are literally the model's weighting, exposed. The engine also computes a confidence score from history count and conditions coverage, which drives the header language and the "probably" hedge.

Showing the sources is the trust mechanism. A recommendation that admits what it's leaning on is much harder to resent when it's wrong.

COVERAGE IS THE PROGRESS BAR — NOT RUN COUNT
0°20°40°60°80°+
COVERED 3 PARTIAL 1 UNKNOWN 4

Coverage is ink, never hue — solid is covered, hatched is partial, hairline is unknown. Pink, teal and grey belong to the verdict (cold, dialed, warm) and are not available here; see AB. A runner with 40 verdicts all at 50° is still guessing in January — so the app asks for verdicts where the gaps are, not just more of them.

BACKGROUND

Confidence is computed per temperature band × condition class, not globally — the same user can be dialed at 50° and guessing at 15°. Band coverage drives three things: the header language, the weighting between personal and cohort data, and which verdict the app asks for next. Every verdict also flows back into the cohort model, so a new user in a dense city inherits a much better prior than one in a sparse region — an argument for launching city by city.

THE HARD DEPENDENCY

Cohort quality is geographic. Launch narrow — one or two cities — so the first users inherit a real prior instead of a global average that fits nobody.

WHERE AI IS NOT USED

Comfort prediction. That's a small model over structured features — auditable, explainable, and correctable. A language model narrating a guess would be the fastest way to lose a runner's trust.

SKIPPABLE BY DESIGN

Every step past O1 can be skipped. A user who bails after the warm/cold question still gets a usable call — worse, but honest about being worse. Nobody photographs 40 garments on day one, and the product shouldn't require it.
