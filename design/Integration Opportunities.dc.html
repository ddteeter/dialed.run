Integration opportunities  /  where the record lives outside the appdialed.run

Your blog says how it fits. dialed.run says how it did.

A garment's record (runs, the conditions it was worn in, the verdicts) published as data, so other sites can render it in their own styling. Each one links back to a dialed.run conditions guide, which is where the search value comes from. biglongrun.com is the first and reference integration.

01 · Real-world conditionsA sibling to the Strava block on apparel reviews. It has the same tabs and the same grammar. Astro renders it at build time and computes every number in it from the general read API (02), the same way it computes its Strava stats. The Strava block answers "how much was it used?". This block answers "in what conditions, and did it work?". Drawn below in neutral blog styling. The real one takes biglongrun's own CSS.

AT REVIEW · LIFETIMESame split as Strava. The blog asks for runs up to the post's publish date (/v1/pieces/:id/runs?asOf=2026-03-04) for At Review, and asks without asOf for Lifetime. Both tabs are computed in Astro from the same run list.
BY CONDITIONS · THE LINK THAT MATTERSThe blog groups runs by feels-like band using /v1/bands, which gives each band's range, whether its guide is published, and its guide URL. A published band is a normal followed link to dialed.run/what-to-wear/{band}. An unpublished one is plain text.
VERDICTS · THE BLOG'S WORDSEach run carries its verdict as a word (way_cold … way_warm). The blog folds them into cold / dialed / warm and picks its own words and colours. The block never uses dialed.run's hues or type. It's credited in the footer, the same way Strava is.
RUN ROWS · LINK TO DIALED.RUNEach date links to the entry on dialed.run (app.dialed.run/feed/entry/{id}). Signed-out readers get the Round 30 #5 landing, which shows nothing of the entry (D-58), then the pitch and Log in / Request an invite. After signing in, they land on the entry. The read-only public view first drawn here is withdrawn.
UNIT PREFERENCESEvery temperature comes in both °F and °C, so biglongrun's existing unit switch drives it with no second request.
02 · The dataA general read API on api.dialed.run. It returns runs and pieces, and callers aggregate for themselves. Nothing in it is shaped for one layout. Every total in 01 (tabs, bands, sky, worn-with, the folded verdict) is computed by the blog. Access is with a personal token (Round 30 #6), and any runner can create one.

THE BLOG COMPUTESRuns worn and feels range come from counting and min/max over the list. Bands come from bucketing feels into /v1/bands. Sky and verdict splits are counts. Worn-with is a count over each run's kit. The date range comes from the first and last start.
SCOPE IS THE TOKEN'SA shared-only token returns shared runs only. A token that includes private entries returns those too, with visibility: "private" and entry_url: null. A blog token should be shared-only.
THE BLOG DECIDES WHAT TO SHOWThe API carries start time and the piece's note because it's your data. The biglongrun block shows the date only, and never shows notes or times. That's a choice in the Astro component, not something the API enforces.
ERRORSA revoked or unknown token gets 401. A deleted piece, or one that isn't yours, gets 404. The Astro component then renders nothing, logs a build warning, and lets the page build.
VERSIONED PATHFields are only ever added under /v1. A rename or removal means /v2.
03 · Turning it onA personal API token from Settings › Account, drawn in Round 30 #6. The per-piece publish toggle first drawn here is dropped, so the token is the only switch. The blog asks for a piece by its id, which is shown on the piece's page and goes in the review's frontmatter (dialedPiece: pc_8f2c41a9) next to the Strava gear id. Revoking the token removes the block on the next build, through the 404 rule in 02.
04 · Other openingsRanked by how much attention each brings, against how much it costs to build. None of these are committed. Marked for a decision.
Shoe reviews tooV1 · SAME BLOCKIf shoes are in the closet, the same endpoint works for them. The Nimbus 27 review would gain "Rain 4 · slippy after fresh rain" as data next to what the review says about it.
Kit line on the Strava activityNOT ADOPTEDOwner: not adopted. dialed.run never stores or shows Strava activity data. The idea was: opt-in, and after a verdict dialed.run would append one line to the activity description: "41°F damp · Dialed · kit via dialed.run". Every follower sees it. It needs Strava's write scope and a brand check with Strava.
biglongrun /compareAFTER LAUNCHCompare two jackets by band: which one was dialed more often at 32–41°F. It reads the same feed and needs no new endpoint.
Other runners' sitesADOPTED · ANY RUNNERAny runner can create tokens (owner, after round 30). Rate limits and the Desk view of token use go with the API build.
