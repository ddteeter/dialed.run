Day 2  /  groups · parked, not scheduleddialed.run

You follow a person. You join a place.

Groups give runs a middle audience between Only me and All runners. Kit advice is local, so the most useful answer to "what do I wear at 34°F" comes from people in the same weather. The only thing that ships before launch is the audience model (docs/product.md). Everything else here is a direction, with the open questions marked.

01 · The model
AudiencePRE-LAUNCH · DECIDEDOnly me · My groups · All runners. It's stored as audience plus group_ids[]. Launch uses only the two ends, and the copy doesn't change.
Auto-share per membershipDIRECTIONEach membership has "Share my runs here automatically". A run set to My groups goes to every group with it on. There's no per-run group picker, because it slows logging and invites mistakes.
Join typesDIRECTIONOpen: anyone can join, and turning auto-share on warns that this is close to sharing with everyone. Request: an admin approves each request. Invite: by link or code only, and never listed.
FollowsUNCHANGEDFollowing still controls whose shared runs appear in your feed. Groups add a feed tab per group, or one Groups tab (open question 5).
TotalsFOLLOWS ROUND 32Group-only runs count in anonymous totals like any other run. In-app "worn by N runners" stays All-runners only. A group's own totals page ("what the club wore this month") needs no threshold, because members already see each other's runs.

03 · Open questionsThese need owner decisions before design starts. Each has a lean.
1Who can create groups?Lean: the owner, or runners the owner approves, at first. Run clubs, plus biglongrun readers as group one. Open to any runner once the Desk can moderate groups.
2Leaving a groupLean: the group loses access to your runs straight away. A group-only run becomes Only me unless you're still in another group with auto-share on. The leave confirm says so.
3Admin powersLean: admins can approve, remove, rename, close the group, and hide a run from the group. They can't see private runs, edit anyone's run, or remove a run from dialed.run (that's the Desk).
4Reports inside a groupLean: they go to the Desk Review queue as today, tagged with the group. Operators can see a reported group-only run.
5Where groups live in the feedLean: one Groups tab next to Following, with a group switcher. A tab per group doesn't scale beyond two.
6Size and count limitsLean: a runner can be in up to 10 groups. No cap on group size, but an open group over 200 members gets a reminder on its auto-share warning.
7Group pages on the marketing siteLean: no. Groups are signed-in only, like entries and profiles (D-58). A public "Lakeside Run Club" page is a later SEO idea, and would show anonymous totals only.
