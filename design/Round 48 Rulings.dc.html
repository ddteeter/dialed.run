Rail: under Review, above Duplicates, since it's a queue that gets work done, not a report. Count: yes, D1's style [n WAITING · m DECIDED TODAY], counting rows rather than runners. A row is one product + field + suggested value. Runners who sent the same value join it ("N RUNNERS"), and the newest filer and their note lead. "2 more runners" opens the rest inline. A different value for the same field is its own row, and the rows sit next to each other. Order: most runners first, then oldest first. Apply (chalk) writes the product row and decides every row for that field. Decline (outline) opens the 104 select inline with "No reason given" (the default), "The maker's page says otherwise" and "Not enough to go on", then Confirm. No Merge: a name correction that's really "this is the same as X" is declined and handled in Duplicates.

A new DISPLAY group after Notifications, before the account and data groups. Label "Theme". Three-way segmented control, a radiogroup with arrow keys (three short options, so not the 104 select): SYSTEM / LIGHT / DARK. Changes the page at once and saves at once, with no Save. If saving fails, the page keeps the theme and the row's message band shows "Couldn't save. This device will keep it." The value is also cached on the device so the first paint is right. Signed out: always system. On sign-in the account's value takes over.
